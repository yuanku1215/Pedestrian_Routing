========================================

- Hacker et al. (2021), Most Diverse Near-Shortest Paths

Why this new formulation exists
- The current single-path routing problem is still a weighted shortest-path problem.
- Under that definition, Dijkstra is the exact reference solution and SQA should not be expected to beat it.
- The new target problem adds an alternative-routing requirement: produce multiple short paths with limited overlap.
- This creates pairwise path interactions, which is where QUBO/SQA becomes more meaningful.

Problem definition adopted for this project
- Base problem family: kSPwLO
- Graph: directed weighted graph G=(N,E)
- Path length/cost: sum of edge weights along the path
- Similarity measure: weighted overlap ratio

Similarity definition taken from kSPwLO
- Sim(p, p') = sum_{e in p intersect p'} w(e) / min(length(p), length(p'))
- In this project, overlap is measured on shared segment_id values.
- Weight field used for overlap can be configured:
  - cost
  - length

Current implementation scope
- Rule name: kspwlo_routing
- Current default: k=2
- Threshold theta default: 0.5
- Near-shortest corridor epsilon default: 0.2
- QUBO overlap handling: soft penalty, not exact hard-threshold enforcement

QUBO variable design
- x_(r,e) in {0,1}
- r = route index, currently 1..k
- e = directed edge in the sidewalk graph
- x_(r,e)=1 means edge e is selected for route r

QUBO objective
- Minimize total route cost across all routes
- Add soft overlap penalty for shared segments across routes

Implemented objective structure
- Sum_r Sum_e c_e * x_(r,e)
- Plus lambda_overlap * overlap_weight(segment) * x_(r,e_i) * x_(r',e_j)
- The overlap coupling is added across route pairs and across directed edges that belong to the same segment_id

Implemented path constraints for each route
- Source out-degree = 1
- Source in-degree = 0
- Target in-degree = 1
- Target out-degree = 0
- Intermediate node flow balance: in - out = 0
- Intermediate node incoming degree <= 1
- Intermediate node outgoing degree <= 1
- Same segment cannot be selected twice within one route

What is aligned with the literature
- Directed weighted graph model
- kSPwLO overlap semantics
- kSPwLO threshold theta as the main overlap control parameter
- kMDNSP-inspired penalty shortest-path heuristic as the classical baseline reference
- Near-shortest corridor epsilon for baseline candidate generation

What is intentionally simplified in v1
- Overlap threshold is not yet encoded as an exact hard QUBO constraint
- The SQA formulation uses a soft overlap penalty instead
- The rule currently defaults to k=2 before scaling to larger k
- Completeness relaxation from kSPwLO is not the default behavior

Baseline heuristic implemented in this repo
- First route: standard shortest path
- Remaining route(s): kMDNSP-style penalty shortest path inside a near-shortest corridor
- Penalized weight: w'(e) = f * w(e) for edges already used by selected routes
- Penalty factor starts from 2.0 and decreases as search fails to find a new acceptable path
- Candidate route must satisfy:
  - simple O-D route
  - near-shortest cost bound
  - overlap threshold theta against already selected paths

Why this baseline is useful
- It keeps the routing logic close to the literature
- It gives a classical non-QUBO reference on the same graph and same path-diversification idea
- It can also be used as an SQA warm start
